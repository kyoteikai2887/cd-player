# 多来源歌词与在线资料 · V1.0.0

适用 **1.0.0**，契约 **0.4.0**。手动“搜索歌词候选”合并 **LRCLIB、QQ 音乐、网易云音乐、酷狗音乐**。LDDC 是整合这些来源的工具；本版接入同类来源，没有要求另装 LDDC，也没有嵌入其 Python/Qt 引擎。已合入候选双语预览与导入后译文显示。

## 本次使用

从“歌词操作 → 搜索歌词候选…”打开，严格查找未命中后选“搜索其他版本”。编辑器中用“导入 → 从在线候选导入…”。原“查找歌词”保留严格 LRCLIB 匹配，不自动采用新增来源宽搜索结果。曲名/歌手只影响搜索，歌手可留空，不改曲目资料。

每份候选显示来源、署名、专辑、时长和版本提示。时长接近不代表演唱版本正确；请对照播放核对。TV Size、电影版和其他演唱者仍可能存在。酷狗歌词搜索可能没有专辑名，保留未知，不拿本地专辑名冒充。合计12项，保留不同来源候选。

没有原文且未打开编辑器时，可明确“使用这份歌词”补进收藏。有原文时只导入草稿，之后由用户保存；旧译文继续遵守原文导入保护规则。取消/冲突/失败不保存，用户 offset 保留。来源给出单独译文时只做安全时间配对，不自动翻译。候选默认原文，实际带译文时可切双语；只显示安全配对的来源译文。导入后实际结果有译文就展开编辑器译文列，提示行数与保留情况。不会为了新译文改变旧草稿的保护规则。

## 服务失败与数据

来源并行，最多20秒；每次网络响应最多10秒，同源间隔至少500ms，新增来源各最多读四份歌词。一家失败仍显示其他可用候选，并提示未完成来源。没有结果但有失败时提示“查询未完成”，不把失败当数据库缺歌。QQ实际出现过部分拒绝，无法保证始终可用。本轮读取普通逐行/纯文本，不提供逐字QRC/KRC或罗马音。

HTTPS只允许明确域名和查询路径，重定向继续核对。新增请求发送曲名、歌手、时长及候选记录信息，不发送文件路径、音频、完整收藏或草稿。不要求账号、密码或用户Cookie。请求标识CDPlayer/1.0.0，联系标识为 https://github.com/kyoteikai2887/cd-player。

JSON缓存在应用私有online-cache/responses：命中七天、成功空搜索一小时，96条/16MiB；QQ请求体参与缓存身份。损坏或拒绝响应不缓存为成功，缓存不随收藏备份恢复或交付包发出。

## 专辑资料与严格歌词查找

## 如何使用

专辑页“更多专辑操作”中查找在线资料，等待候选出现，再核对发行地区、年份、品番、碟数、曲目和封面，按字段选择采用。默认不勾选手动整理过的字段；需要替换时逐项确认。取消或关闭候选不会保存。查找后资料库有任何内容变更，旧候选整次拒绝，请重新查找；冲突结果同时带最新快照，不自动重试。

在曲目菜单或歌词页使用“查找歌词”。已锁定的歌词须先由用户解除锁定；仅填补缺失原文，不替换已有原文、译文或用户标记的纯音乐/念白。LRCLIB 本版作为原文源，不提供单独翻译服务，所以查找不会凭空生成译文。有原文时可以查询，但不会替换，替换请使用导入或编辑。

本版仅由明确的查找操作联网，启动、播放、导入和重新扫描不会自动发送查询。断网不影响本地播放。查询中和失败时保留已有歌词与草稿；取消不提示失败；关闭候选后迟到结果不再重新打开窗口或弹通知。

## 匹配与边界

MusicBrainz 优先使用已从完整逐轨 EAC 日志得到的 Disc ID，没有命中时按品番或专辑名/艺术家搜索。每次最多展示三个完整发行版本；同一 Disc ID 可能关联多个版本，因此始终由用户审核，不能把相同光盘目录等同于唯一正确封面。封面按具体 release ID 从 Cover Art Archive 获取 500px 图，不按 release-group 借用另一版封面。本版不做模糊 TOC 查询、声纹或自动上报。

曲目字段只有在整张本地碟的曲目数、唯一曲号及对应时长吻合时才提出修改；时长差不超过 2 秒，文本匹配缺少时长时不提出曲目替换。精确 Disc ID 可补充缺失的时长条件。缺碟或曲目不匹配仍可审核专辑资料，并在候选注明；不会替用户改写版本类型、拆分 CV 署名或猜作品分组。采用部分字段、只收录部分碟或曲目无法完整对应时，状态保持 partial。

LRCLIB 核对归一化后的曲名、完整歌手署名和专辑名，并严格要求实测时长差 ≤2 秒。先按四项查询；未命中时搜索并在本地再筛选，多个完全符合的记录也不静默选择。不同版本、署名差异或库内缺失可能找不到，不能因此认定曲目无歌词。提供商的 instrumental 标记不改变用户分类。

歌词返回后再次检查曲目、专辑和歌词 revision 及锁定状态；查询期间手动保存、修改匹配资料、移除曲目或取消，迟到结果不落库。补全保留用户 offset，文件 offset 由共享解析器归一化一次。保存结果通过同一事务及备份机制持久化；主/迷你和编辑器以新快照更新。

## 请求、缓存与数据

请求带 CDPlayer/1.0.0 及项目网址。实际查找会发送曲名、歌手、专辑、时长或 Disc ID/品番；不发送文件路径、音频、完整收藏或草稿。封面服务收到发行 ID。HTTPS 请求只访问服务及封面归档的允许域名，重定向逐次检查，图片通过本地鉴权地址显示。

MusicBrainz 请求间隔至少 1.1 秒，LRCLIB/封面至少 500ms，Retry-After 延后下一次请求。单次网络请求含响应读取最多 10 秒，资料任务最多 45 秒，歌词任务最多 30 秒；普通动作沿用 5 秒预算并立即返回 started。网络失败不会缓存成成功。

应用资料目录的 online-cache/responses 缓存 JSON：命中 7 天，404/空搜索结果 1 小时，最多 96 条且磁盘及内存中的序列化内容各 16MiB。缓存失败不妨碍查询；不随收藏备份恢复，也不随交付包发出。封面通过已有 covers 内容哈希缓存，与本地封面一样持久保留，未新增封面清理策略。在线返回的歌词仅存入本人的收藏/私有缓存，交付证据没有完整歌词。


## 来源与边界

在线适配在开发期通过已获授权的真实 CD 查询验收；查询结果仅属于当次结果，不表示服务覆盖率或永久可用。正式测试使用可控响应，不向外上传用户音频、路径或草稿。数据库、署名与版本差异仍可能使搜索无结果。

参考服务：MusicBrainz、Cover Art Archive、LRCLIB；多来源普通响应的接口结构参考 LDDC 项目公开资料，使用独立适配器，未复制其解密、登录、指纹或 Python/Qt 运行时。
