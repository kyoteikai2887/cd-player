## 后台与关闭

开发源码可运行 `node scripts/background-native-soak.mjs 1800`：默认两种引擎各至少30分钟，总计至少一小时；每种模式复用同一原生程序、后台服务和独立资料目录，循环至指定时长后完成当前队列。两窗口隐藏，没有调试器连接；原创合成音频静音，包含连续重复曲目、自然播完、暂停恢复、重扫和轮次末的迷你/主窗口切换。轮次之间会短暂显示窗口并自然暂停，不宣称整段不停顿，也不保证逐采样无缝衔接。

报告位于 `.cache/background-soak-时间戳/`，记录实际时长、队列轮次、操作响应、失败和资料锁重开。参数单位是每种模式的秒数，60到86400；正常用户版不包含原生测试入口。脚本的默认时长只是复跑配置，以实际报告为准，不代表每次交付已完成一小时测试。

`node scripts/lifecycle-native-smoke.mjs` 只对自己创建的隔离原生程序做三次强制终止，再正常启动并退出：检查后台随父程序消失、锁释放、收藏字节与设置保留。测试不会终止用户正在运行的播放器，也不替代断电或系统崩溃检查。

## 设备与休眠（人工、可在后续集中做）

选择一首较长曲目，音量保持舒适，先记下曲目和播放位置。

1. 播放时切换系统默认输出，或拔下正在使用的耳机。记录是否仍可暂停、音量操作是否响应；若出现输出不可用提示，重新连接后明确点击播放，确认不会跳到另一首或重复弹出提示。
2. 分别在播放和暂停状态下进行正常系统睡眠，再唤醒。确认界面重新响应、暂停状态不会自行播放、两窗口显示同一曲目。若输出失效，保留提示和日志，再点播放重试。
3. 主窗口与迷你窗口各拖到另一块显示器，检查100%、150%、200%缩放下的文字、控件和歌词高度；歌词开关改变高度时迷你仍留在工作区。只在实际具备这些屏幕或缩放条件时记录“通过”。

这些操作由用户在方便时执行，自动检查不主动改变系统音频设备、休眠或全局缩放。没有相应硬件的项目标为“未覆盖”，不算失败或通过。
