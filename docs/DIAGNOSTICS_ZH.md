# 故障记录与后台检查 · V1.0.0

当前版本1.0.0，契约仍0.4.0。本地诊断自core.17加入，候选界面在core.18接入，日志规则不变，没有联网日志或遥测。收藏、设置和后台快捷键沿用。

## 遇到问题时保留什么

运行后，应用资料目录 `%APPDATA%\local.cdplayer.v1\logs` 会生成 `diagnostics.ndjson`，以及最多三个轮转文件 `diagnostics.1.ndjson` 至 `diagnostics.3.ndjson`。每个最多256KiB，应用生成的四个文件合计最多1MiB。需要反馈时，可先从托盘退出，再复制这几个日志文件，并说明大约发生时间及正在做的操作。不用发送收藏文件、音乐或歌词缓存。

记录包含应用版本、启动/关闭、核心连接状态的变化，以及操作类型、匿名请求ID、执行阶段、耗时和结果码。不记录动作参数、曲目或专辑名称、文件路径、歌词、查询词、邮件地址、服务返回正文或错误消息。日志仅留在本机；不会随交付包包含用户实际日志，也不会自动上传。

日志后台写入，内存队列限制128条。队列满或磁盘异常时丢弃诊断记录，不等待日志再处理播放/保存；正常退出最多等250ms收尾。异常终止可能缺最后几条记录，因此没有日志不能证明操作未发生。日志不是收藏备份，不用于恢复歌词或资料。

## 如何定位响应超时

阶段为sent（原生发出）、received（核心页面收到）、handled（处理得到结果）、published（相应快照已发布）。响应超时会保留最后到达的阶段：

- 只到sent：优先检查核心页面是否冻结、事件通道或系统调度。
- 到received但未handled：检查具体操作/本地服务/解码响应。
- 到handled但未published：检查快照发布通道。
- 到published仍未返回：检查结果回传通道。

阶段记录本身是可丢弃的辅助证据，应结合实际界面、资料快照和测试报告判断。结果仍遵守原有超时、revision冲突与“快照先于确认结果”规则；不能因为某次回复超时就假定所有写入都没有发生。

core.16出现过一次原生扫描响应超时，随后重跑通过，本节点没有把未确定的根因称为已经修复。新的阶段记录用于后续定位；需要继续小时播放、真实设备/休眠、多屏/DPI验收。

## 本节点自动检查

在独立静音原创音频库、未连接检查器的情况下，普通及强制流式两种模式分别做18秒双窗口隐藏待机，然后12个队列项连续播完（含相邻重复曲目）。播放中穿插重新扫描、暂停/恢复，最后恢复窗口并退出、重开资料锁。两模式共52个原生操作结果，无响应超时；本机样本中位15ms、P95 22ms、最大85ms。曲目、队列项、歌词归属和原音频/附件哈希检查通过。

这是约四分钟的有限联调，不能代替小时压力或物理声卡验收，也不承诺流式逐采样gapless。原生17项基础联调与输出关闭/重试另行记录在TESTING.md。
