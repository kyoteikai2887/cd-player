# 契约 0.3.0：从收藏移除专辑

2026-10-04。用户在 R2.1 试用后追加“删除已添加”的需求。本节点实现**按整张专辑从收藏移除**，原始音频、封面、LRC、log/CUE 均保留。契约由冻结的 0.2.0 显式升级到 **0.3.0**；唯一新增公共动作如下，其他类型与原行为不变。

```ts
{ type: 'removeAlbum'; albumId: string; baseLibraryRevision: number }
```

UI 打开确认框时保存 `snapshot.library.revision` 作为 `baseLibraryRevision`，同时显示当时看到的专辑名称、曲目数和播放/草稿影响。点击确认时提交这个值，不临时改为最新值。播放进度刷新不改变 library revision。

核心检查整个资料库 revision。任意收藏资料或歌词在确认期间已提交变化时，整次返回 `conflict`，没有部分移除。最新快照在结果返回前发布。UI 请保留确认上下文，提示用户检查最新内容后**再次明确确认**，不要自动以新 revision 重试。无效参数返回 `invalidAction`；在同一 revision 下目标不存在返回 `notFound`；备份或保存失败返回 `io`。失败只经 ActionResult 返回，不重复发 Notice。

成功返回 `{ ok: true, status: 'applied' }`，此前 main/mini 已收到统一快照：

- library revision 增加 1，移除该专辑及 `track.albumId` 属于它的全部曲目；其他专辑资料保留。
- 清理这些曲目的所有队列项，包括重复出现的项。剩余 entry.id、顺序和正在播放的其他曲目的进度不变。
- 如果当前曲目被移除，停止音频，`status='idle'`、currentTrackId/currentEntryId 为 null、index=-1、position/duration=0、lyrics=null；保留剩余队列、音量、静音、随机和循环设置，不自动跳到另一首。用户再次按播放可启动剩余队列。
- 如果当前曲目属于其他专辑，继续播放；预加载的后继曲目按剩余队列重新计算。
- 关闭被移除曲目的 lyricsEditor、该专辑的 metadataReview，取消正在针对它们进行的文件操作。UI 中相关编辑草稿的放弃确认由 Claude 在提交前完成，其他专辑草稿不得受影响。

后端在成功移除前强制保存一份当前应用资料的备份，失败则拒绝移除。随后只清理应用内资料、歌词和文件/封面映射，不调用源文件删除、移动或标签写入。缓存封面实体暂不回收。备份恢复沿用已有工具，暂不新增撤销接口。

移除记录持久化到私有资料库；**重新扫描不恢复这些已移除的文件身份**。用户明确重新导入包含这些原文件的目录，可重新加入并按文件原有标签/歌词建立记录；移除前的应用内手动修改可以从备份恢复。已在移除前启动的导入，即便文件选择/扫描稍后才完成，也不会恢复它们。身份目前按路径建立，文件搬家后的关联迁移仍是后续工作。

本轮不新增单曲删除、根目录删除、批量移除或删除磁盘文件。DemoBridge 支持同一公共动作、队列与编辑器规则；真实文件、扫描排除和备份由 LocalSession/本地服务负责。既有 fixtures 路径和条目、UI 内容与依赖均未改。

旧 schemaVersion=1 的资料库缺少私有排除字段时仍可读取；读取老资料不强制改变用户强调色、收藏路径或系统设置。旧 0.2.0 原型不理解新排除行为；本次交接统一使用 0.3.0 基线，不叠加旧源码包。
