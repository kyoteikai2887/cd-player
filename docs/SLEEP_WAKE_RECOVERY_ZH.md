2026-10-08 的 V1.0.0 现场：约 18:19 进入现代待机，20:38 唤醒。原生窗口仍在，内容空白或透明；缩放、最小化还原及 Ctrl+R 均未恢复。经鉴权的本地服务健康检查正常，原生进程有响应；界面心跳在 18:50 停止。用户确认没有未保存草稿，从托盘退出并重新打开后恢复，日志重新出现 ready=true。

已确认故障边界在界面渲染／通信恢复侧，尚未确认触发空白的根因。没有证据证明收藏损坏或 GPU 崩溃；当前发行版没有采集 WebView2 的 ProcessFailed 事件，无法追溯准确类型。Ctrl+R 没有反应也不能证明原生 Reload API 已执行。本次不主动令用户电脑休眠，不删除资料库或 WebView2 配置。

## 候选版改动

- 修补独立复现的心跳缺口：HTTP 探测和原生上报各自有 1500ms 超时。单次上报不返回不再永久阻断后续心跳。重新获得焦点、页面重新显示后中断旧等待并重试；不改变音频播放状态。
- 窗口显示或获得焦点时，通过 WebView2 的 Resume API 恢复主窗口和迷你窗口；不导航、不丢草稿。此项针对可能的挂起状态，不能保证解决所有渲染异常。
- 加入 WebView2 ProcessFailed 类型和界面准备、初始化异常的本地记录。只记录已知窗口、固定事件名和有限数字类型，不记录错误文本、音乐资料、查询词、路径或崩溃转储。
- 托盘新增“恢复界面…”。始终先显示原生确认，明确会停止播放并丢弃未保存草稿；已保存收藏和设置保留。确认期间草稿状态变化会拒绝恢复，用户需要重新确认。随后重新加载两个界面；仍不能恢复时可从托盘退出后重开。
- 没有自动刷新、UI 样式变更或契约变更。使用已锁定的 webview2-com 0.39.1、windows-core 0.62.2；没有新增第三方包版本；补齐 WebView2 三个组件缓存包中缺少的上游 MIT 正文，windows-core 许可沿用既有集合。

## 用户复测

1. 先从旧版托盘退出，再打开候选版；沿用已有收藏，无需重导入。核对正常播放和主／迷你切换。
2. 在没有未保存草稿时，托盘“恢复界面…”先选取消，确认不影响现有状态；再确认一次，界面恢复、播放停止，收藏仍在。
3. 按平常方式做一次较长休眠，分别留意暂停与播放、隐藏到托盘后的恢复。无需为了验证强行反复休眠。若仍空白，记录时间，先试恢复入口；随后保留本地 diagnostics 日志。
