# 资料备份与离线恢复 · 核心 M2

2026-10-03，核心 0.2.0-r1.1-core.2；共享契约仍为 0.2.0。本轮由 Codex 并行完成，不改 Claude 的 R2 UI 接口，也不需要她暂停工作或更换基线。

## 已完成的行为

已有资料库在本次启动的第一次写入前，先备份上一个已提交版本。之后每 10 分钟的首次写入再备份，避免连续调整偏移或主题时不断复制。初次创建空库不备份空白默认值；第一次保存后的再次写入会开始保护已保存资料。手动快照随时可建。

备份放在所选应用资料目录的 backups/，每份使用独立编号、时间和 SHA256 校验。只记录已提交状态，草稿/取消写入不会进入备份。自动备份失败时本次写入失败，快照和当前资料文件仍保持旧版本，UI 可保留草稿。备份暂不自动删除。

内容包括资料库、歌词/译文/offset/锁定、人工保护字段、旧歌词归档、用户主题和设置、资料根目录、音频及封面索引。**不复制音频、LRC 原文件或封面缓存实体。** 这是本地资料恢复机制；搬迁时还需保留原音乐和应用 covers/。

## 当前使用方式

自动备份由真实本地入口直接执行，模拟 DemoBridge 不访问磁盘。手动工具在项目目录运行；默认数据位置 .local-data，可以用 --data 指定隔离目录。

```text
node scripts/backup.mjs list
node scripts/backup.mjs create
node scripts/backup.mjs restore --id <list 显示的完整备份编号>
```

创建和恢复需要先关闭使用该资料库的本地播放服务。恢复前持有同一 writer.lock；若仍有进程或异常退出留下锁，会拒绝操作，不能绕过锁强制恢复。list 只读，列出可恢复备份及校验失败记录。

恢复先验证版本、内容结构和 SHA256；损坏或编号无效时不替换资料。恢复前的 library.json 即使已经损坏，也会逐字节保存在 recovery/library-before-restore-*.json；然后原子恢复。恢复后重新启动播放器，旧 UI 连接/草稿不会继续向已回退的 revision 写入。仍不自动猜测或删除异常锁。

尚未接入设置里的恢复页面；这一产品入口不抢占 Claude 本轮 UI 范围，之后按统一契约对齐。真实用户收藏与跨设备备份尚未验收，本轮实测使用独立临时资料，并运行了真实 CLI 子进程。
