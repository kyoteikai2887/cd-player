# 音乐文件夹移动与重复导入

版本：0.3.0-r2.2-core.14，接口仍为 0.3.0。

## 怎么使用

旧版升级后，先在音乐仍能正常读取时执行一次“重新扫描”。新导入的音乐自动建立完整文件指纹；已有资料在扫描时补齐。首次需要读取完整音频，硬盘、光盘盒或网络盘较慢时会多花一些时间，可取消。

以后移动完整专辑文件夹，使用已有的“导入文件夹”选择新位置。整张专辑的文件内容、原始碟号和曲号完全匹配且关联唯一时，更新文件位置，保留专辑/曲目编号、加入时间、手动保护字段、保存的歌词及其 revision、手动封面。重复导入已知专辑的完整副本也复用记录。曲目编号不变，原队列的关联继续有效。

文件位置写入前总会额外备份最新应用资料，不受普通十分钟备份间隔限制；备份失败则不保存新位置。应用读取音乐，移动操作由用户完成；不会改写音频、标签、封面、LRC、log 或 CUE。

旧目录已离线时，重新扫描保留记录并标记文件不可用，继续扫描其他正常目录。关联完成后，没有任何剩余文件记录的旧扫描根目录会移出扫描列表；仍包含其他曲目的旧目录保留。

## 不确定时的处理

- 只搬了部分曲目、标签/文件字节发生变化、或旧库已经存在多份相同专辑，均不强行关联。无法唯一关联会提示并保留记录，需要人工核对；本版不自动清理过去产生的重复专辑。
- 旧版本从未建立指纹且原文件已经不可读时，不能仅凭标题和时长确认是同一份音乐。先恢复原目录并重新扫描，再移动；无法恢复时可以导入新位置，但旧编辑资料不会自动转移，不要急着移除旧记录。
- 无标签文件会使用文件名推断曲号。改名导致曲号变化时可能无法整张关联；同音异文件格式或重新编码也不视为字节相同。
- 同时扫描已知路径和副本时优先使用已知路径。单独明确导入副本时会改用本次选择的位置。
- 未保存的界面草稿仍由界面管理。已保存歌词保持 revision；资料变化继续遵循原有冲突规则。

“从收藏移除”的排除规则继续有效：自动扫描及移除前启动的导入不能借新路径、部分副本或 WAV 改名将内容加回。移除后主动重新导入可以重新加入；删除的旧编辑资料需要从移除前备份恢复，路径关联不会绕过这一约定。

## 已验证与边界

新增 14 项正式 Node 测试，包括移动/副本/完整性、相同标题时长不同音频、歧义、手动字段与歌词、旧资料补齐、并发修改和移除、备份与失败、重启、取消、离线目录与 HTTP 音频读取。正式总计 159 Node + 129 UI = 288 项通过，完整类型检查和构建通过。独立合成库移动后再进行 Windows WebView2 联调；结果见 TESTING.md 和包内 evidence。

这是完整文件 SHA256 核对，不是音频解码后的声纹，也没有重新验证 AccurateRip。每次扫描增量读取文件，哈希缓冲为 256KiB；尚未测量真实 300 首 FLAC 在各种磁盘上的耗时、长时后台扫描或网络盘中断。默认收藏和真实音乐没有为本节点测试而改动。
